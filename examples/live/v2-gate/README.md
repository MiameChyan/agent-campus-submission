# 归档：v2（第一次外部评审修复后）真实模型运行记录

v2 在 v1 的基础上做了以下修改：提交闸门改为引文逐字匹配，并新增数值核对；提示词禁止“确认前先按某一方执行”的临时建议；C02 / C04 断言收紧。这里保存的是第二次外部复查（Codex + DeepSeek）之前的运行记录，不代表最终版本的表现。最终版本的结果见 [examples/live/](../report.md)。本目录下的报告都已**按当前（v4）断言重新判定**，没有重跑模型。

| 内容 | 按 v4 断言重新判定 | 说明 |
|---|---|---|
| `C*.output.json` / `C*.trace.md`，[report.md](report.md) | 10/11 | C04 把“发票提交”和“报销申请提交”当成同一口径，没有说明知识库只规定了报销申请的期限 |
| [stability/](stability/report.md) | 6/9 | C04 的 3 次运行同样没有区分发票与报销申请；C02、C10 全部通过 |

第二次复查还指出了 v2 闸门的缺口：用户问题中的数值被当成依据、条件与数值的对应关系不核对、中文数字可以绕过、冲突结果不强制写资料缺口、资料外结果可以携带无关引用。用当前闸门离线回放这批输出（`python scripts/replay_gate.py examples/live/v2-gate`），全部 11 + 9 份都能通过，也就是说这些缺口在 v2 的真实运行中没有实际触发，修复主要用来堵住可构造的反例。
