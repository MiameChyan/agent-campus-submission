# 04 AI 使用说明

## 使用的工具

| 工具 | 用途 |
|---|---|
| Claude Code（模型 Claude Opus 5.5） | 需求梳理、方案讨论、编写代码 / 测试 / 合成数据 / 文档、运行测试与评测 |
| DeepSeek `deepseek-flash` | 项目本身调用的模型（Agent 的决策者），不参与写代码 |

## 分工：哪些是 AI 做的，哪些是我做的

工作方式：**先讨论、定稿，再实现**。每一个关键取舍都由我先提出或确认，然后才让 AI 动手写代码。

| 环节 | 我的决定 / 修改 | AI 的贡献 |
|---|---|---|
| 选题 | 从四题中选了第 3 题（与我已有的 RAG 项目经验相关） | 总结四道题的要求，给出推荐理由 |
| 模型 | AI 最初按我旧项目的配置提出用硅基流动接口，**我改为 DeepSeek 官方接口的最新模型（V4.1 Flash）** | 查阅官方文档，确认模型名 `deepseek-flash`、思考模式需要回传 `reasoning_content`、strict 模式需要 `/beta` 端点 |
| 架构 | AI 初版方案只有 CLI 和一个约 200 行的简单循环。**我要求前后端分离（选定 Python FastAPI），并要求参考我正在学习的《深入理解 AI Agent》中的设计，把 loop 做得更完整** | 对照书中第 2 章状态栏、第 3 章 Agentic RAG / 文件系统范式、第 8 章安全闸门，设计 harness |
| 知识库 | AI 初版是扁平文档 + BM25。我本机有 Milvus，也有 embedding 服务，但**我判断层次型更合适，向量检索太重，要求在文档中写明放弃的原因** | 按“文件系统范式”设计目录 / 大纲 / 原文三层，以及 browse / outline / read_section 工具 |
| 知识导入 | **我提出“文章导入”是否需要实现**，讨论后确定：不做 PDF 解析和自动摘要，只做加载 + 校验 + 新增文档模板 | 分析取舍；实现校验与 `src.kb.check` |
| 项目结构 | **我要求参考官方示例仓库的结构，把提交项目放在子文件夹（根目录留给讨论文档），并 fork 到自己的 GitHub**；确定 `src/` 分层、CLI 为主入口、预期写在 input.json、前端只做最基础功能 | 按决定搭建目录 |
| 配置 | **我要求补上 `.env.example`**（AI 起初只建了 `.env`） | 编写两份文件，确认 `.env` 已被 git 忽略 |
| 前端 | AI 第一版是 Vue 单页，表格式展示 trace。**我要求改成接近真人使用的对话界面（参考 ChatGPT / DeepSeek 和我自己的 TRPGMind 项目），改用 React；技术栈保持完整（TypeScript、路由、状态库），但功能要精简** | 按 TRPGMind 的设计 token 重写为对话界面；后端补上“停止”时的取消逻辑 |
| 代码、测试、数据、文档 | 审阅方案和运行结果 | 编写全部代码（约 1800 行 Python + React 前端）、57 个测试、8 篇合成文档与 11 个用例、本目录文档初稿 |

## 发现并修正的问题（过程记录）

| 问题 | 发现方式 | 修正 |
|---|---|---|
| 第一次真实调用返回 401 | 运行冒烟测试；AI 只检查了密钥格式（不输出密钥），发现不是 `sk-` 开头 | 我确认误把 trace id 粘贴成了密钥，重新填写后正常 |
| C10 断言两次误判（模型结论正确，却被判失败） | 主评测和稳定性复跑各出现 1 次失败，人工查看答案原文 | 断言最终改为检查“答案第一行”，每次都用同一批输出重新判定，并补回归测试（详见 03 第 4 节第 1 条） |
| 冒烟测试发现控制台中文乱码（Windows GBK） | 运行输出 | CLI 和评测脚本统一把 stdout/stderr 切换为 UTF-8 |
| AI 写的补丁脚本在 heredoc 中把 `\n` 转成了真实换行，导致语法错误 | 运行评测脚本时报错 | 直接修正源文件后重跑 |
| React 页面发送问题后白屏 | 在浏览器中实际提问，读取控制台错误 | 新版浏览器的 `scrollIntoView` 返回 Promise，箭头函数把它作为 effect 的返回值，导致 React 卸载时出错；改为块语句 |
| 前端“停止”只断开了连接，后端仍会跑完、继续消耗 token | 方案评审时发现 | harness 增加 `should_stop`，服务端检测到断开后置位，在下一轮模型调用前以 `cancelled` 结束，并补测试 |

## 验证方式

- 自动化：`python -m pytest -v`，57/57 通过（[记录](../examples/test-results.txt)）。
- 真实模型：`python scripts/run_eval.py --mode live`，11/11 用例通过（[报告](../examples/live/report.md)）；C02、C04、C10 另外各复跑 3 次，9/9 通过（[报告](../examples/live/stability/report.md)）。
- 人工：逐个阅读真实模型的 trace（动作序列和 reason 是否合理、引用原文是否支持结论），据此在 03 中记录了 C05“无依据补充”、C06a“效率偏低”等问题，这些都不是自动断言能发现的。
- 前端：在浏览器中提问“报销期限多久？”，确认检索过程实时展开、结束后自动收起，结果显示冲突提示和两条引用；追问“那年假有几天？”时自动带上历史；点击“停止”后该轮结束。
