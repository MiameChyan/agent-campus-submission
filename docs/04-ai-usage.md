# 04 AI 使用说明

## 使用的工具

| 工具 | 用途 |
|---|---|
| Claude Code（模型 Claude Opus 5.5） | 需求梳理、方案讨论、编写代码 / 测试 / 合成数据 / 文档、运行测试与评测 |
| DeepSeek `deepseek-flash` | 项目本身调用的模型（Agent 的决策者），不参与写代码 |

## 分工：哪些是 AI 做的，哪些是我做的

工作方式：**先讨论、定稿，再实现**。每一个关键取舍都由我先提出或确认，然后才让 AI 动手写代码。

| 环节 | 我的决定 / 修改 | AI 的贡献 |
|---|---|---|
| 选题 | 从四题中选了第 3 题（与我已有的 RAG 项目经验相关） | 总结四道题的要求，给出推荐理由 |
| 模型 | AI 最初按我旧项目的配置提出用硅基流动接口，**我改为 DeepSeek 官方接口的最新模型（V4.1 Flash）** | 查阅官方文档，确认模型名 `deepseek-flash`、思考模式需要回传 `reasoning_content`、strict 模式需要 `/beta` 端点 |
| 架构 | AI 初版方案只有 CLI 和一个约 200 行的简单循环。**我要求前后端分离（Python FastAPI 后端 + 独立前端），并要求把 loop 做完整，确定了如下架构：**<br>① 上下文组装：系统提示 + 会话记忆 + 本轮问题；每轮另外生成一份“状态栏”（剩余预算、检索计划、证据台账、最近的错误与建议），只附在本轮上下文末尾，不写入历史<br>② 模型决策：一次可以并行发出多个工具调用，工具包括检索、目录浏览、文档大纲、读原文、更新计划、追问、提交<br>③ 工具执行：处理超时、对错误分类（是否可重试、修复建议）、提示重复调用；工具失败时代码不自动重试，交给模型决定<br>④ 观察与记录：结果写回上下文、更新证据台账，每一步记入执行轨迹<br>⑤ 提交闸门：提交时校验引用是否来自已读原文且逐字一致，不通过就把原因退回给模型修正<br>⑥ 执行上限：模型轮数与工具调用次数双重上限，超出时返回明确的未完成状态<br>⑦ 安全边界：检索到的内容只作为资料，不作为指令 | 按该架构实现主循环、状态栏、提交闸门与工具层，并补充对应测试 |
| 知识库 | AI 初版是扁平文档 + BM25。我本机有 Milvus，也有 embedding 服务，但**我判断层次型更合适，向量检索太重，要求在文档中写明放弃的原因** | 按“文件系统范式”设计目录 / 大纲 / 原文三层，以及 browse / outline / read_section 工具 |
| 知识导入 | **我提出“文章导入”是否需要实现**，讨论后确定：不做 PDF 解析和自动摘要，只做加载 + 校验 + 新增文档模板 | 分析取舍；实现校验与 `src.kb.check` |
| 项目结构 | **我要求参考官方示例仓库的结构；本地把提交仓库放在工作区的一个子文件夹里（工作区根目录留给讨论文档，不进入仓库），并 fork 到自己的 GitHub**；确定 `src/` 分层、CLI 为主入口、预期写在 input.json、前端只做最基础功能 | 按决定搭建目录 |
| 配置 | **我要求补上 `.env.example`**（AI 起初只建了 `.env`） | 编写两份文件，确认 `.env` 已被 git 忽略 |
| 前端 | AI 第一版是 Vue 单页，表格式展示 trace。**我要求改成接近真人使用的对话界面（参考 ChatGPT / DeepSeek 和我之前做过的一个 React 项目），改用 React；技术栈保持完整（TypeScript、路由、状态库），但功能要精简** | 沿用该项目的配色、圆角等设计规范，重写为对话界面；后端补上“停止”时的取消逻辑 |
| 可扩展性 | AI 列出了一批改进项（知识库缓存、历史截断、CI 等）。**我决定优先做检索可插拔、多模型适配和工具热加载，其余以后再说**；并确定向量存储默认用内存、Milvus 可选，多模型只做适配、不用其他家的密钥验证，插件放在 `src/tools/plugins/` | 设计检索器接口、提供方配置与适配器、插件机制，补 31 个测试，用真实模型做回归 |
| 代码、测试、数据、文档 | 审阅方案和运行结果 | 编写全部代码（Python 后端 + React 前端）、115 个测试、8 篇合成文档与 11 个用例、本目录文档初稿 |

## 发现并修正的问题（过程记录）

| 问题 | 发现方式 | 修正 |
|---|---|---|
| 第一次真实调用返回 401 | 运行冒烟测试；AI 只检查了密钥格式（不输出密钥），发现不是 `sk-` 开头 | 我确认误把 trace id 粘贴成了密钥，重新填写后正常 |
| C10 断言两次误判（模型结论正确，却被判失败） | 主评测和稳定性复跑各出现 1 次失败，人工查看答案原文 | 断言最终改为检查“答案第一行”，每次都用同一批输出重新判定，并补回归测试（详见 03 第 4 节第 1 条） |
| 冒烟测试发现控制台中文乱码（Windows GBK） | 运行输出 | CLI 和评测脚本统一把 stdout/stderr 切换为 UTF-8 |
| AI 写的补丁脚本在 heredoc 中把 `\n` 转成了真实换行，导致语法错误 | 运行评测脚本时报错 | 直接修正源文件后重跑 |
| React 页面发送问题后白屏 | 在浏览器中实际提问，读取控制台错误 | 新版浏览器的 `scrollIntoView` 返回 Promise，箭头函数把它作为 effect 的返回值，导致 React 卸载时出错；改为块语句 |
| 前端“停止”只断开了连接，后端仍会跑完、继续消耗 token | 方案评审时发现 | harness 增加 `should_stop`，服务端检测到断开后置位，在下一轮模型调用前以 `cancelled` 结束，并补测试 |
| 回归评测覆盖了文档引用的原始记录 | 重跑全部用例后，发现 03 中引用的具体现象（C05 的非法 JSON、C10 的闸门退回）在新输出里不存在了 | 原始记录从 git 恢复，回归结果单独保存（现归档在 `examples/live/v1-initial/regression-plugins/`）；评测脚本增加 `--out-dir` 参数，避免以后再覆盖 |
| **外部评审（Codex）指出的两个问题**：① C02 / C04 的断言允许只追问不列冲突，零引用的“请问适用哪份制度？”也能通过；② 引文真实但可能支撑不了结论（引用 30 天原文回答 60 天也能过闸门），且删掉原文空格的引文也被接受 | 我把 Codex 的意见交给 Claude Code 复现，三个反例全部成立；复核旧版输出时又发现，C02 / C04 的 8 次真实运行全部含有“确认前先按 15 天执行”这类替用户选边的建议 | 闸门改为逐字匹配并新增数值事实核对；提示词禁止临时选边建议、要求说明资料缺口；C02 / C04 断言只接受冲突待确认并拦截选边建议；补 10 个测试；旧记录归档到 `examples/live/v1-initial/`，用新版重新跑全部真实模型评测 |
| **第二次外部复查（Codex + DeepSeek）**：① 用户问题中的数值被当成依据（“报销期限是 60 天吗？”→“是，60 天”能通过）；② 条件与数值的对应不核对（“满 10 年有 7 天”能通过）；③ 中文数字可以绕过；④ 冲突结果不强制写资料缺口、资料外结果可以携带无关引用（Codex 复跑 C03 时实际出现）；⑤ C02 / C04 漏拦“请按 D02 的 15 天执行”“按 D02 的期限提交即可”，也不要求请求确认；⑥ C04 把“发票”和“报销申请”混为一谈；⑦ C01 / C03 / C09 断言偏松；⑧ 归档报告用的还是旧断言，与归档说明矛盾 | 我把两份报告交给 Claude Code 逐条核对，确定修复范围：除“仓库里写入最终 SHA”（一个提交无法包含自己的 SHA，题目要求填在提交表单里）外全部修复 | 闸门新增条件—数值配对、中文数字换算、状态约束，用户数值不再算依据；提示词补充“对象不一致要说明差别”“gaps 只写缺少的信息”“中立地请求确认”（例子刻意不用测试用例里的发票场景）；五个用例断言收紧；新增离线回放脚本 `scripts/replay_gate.py`，用新闸门回放全部历史输出，发现并修正了闸门误伤；补 17 个测试；v2 记录归档到 `examples/live/v2-gate/`，归档报告全部按最新断言重新判定；用最终版本重跑真实模型评测 |
| **修复本身引入的误伤**：v3 首次运行中，一次 C04 因闸门连续 3 次退回“1 天”而以未完成结束；另一次 C10 被断言误判 | 我要求先查清原因再决定 | 查明是中文数字换算把“同一天 / 唯一年限”读成了数值，以及模型输出字面 `
` 导致断言取错结论；修正后补回归测试、改进退回信息（附原始写法）和执行记录（附被退回答案的片段），v3 运行归档到 `examples/live/v3-attempt/`，再用最终版本重跑 |

## 验证方式

- 自动化：`python -m pytest -v`，115/115 通过（[记录](../examples/test-results.txt)）。
- 真实模型：`python scripts/run_eval.py --mode live`，11/11 用例通过（[报告](../examples/live/report.md)）；C02、C04、C10 另外各复跑 3 次，9/9 通过（[报告](../examples/live/stability/report.md)）。
- 人工：逐个阅读真实模型的 trace（动作序列和 reason 是否合理、引用原文是否支持结论），据此在 03 中记录了 C05“无依据补充”、C06a“效率偏低”等问题，这些都不是自动断言能发现的。
- 前端：在浏览器中提问“报销期限多久？”，确认检索过程实时展开、结束后自动收起，结果显示冲突提示和两条引用；追问“那年假有几天？”时自动带上历史；点击“停止”后该轮结束。
