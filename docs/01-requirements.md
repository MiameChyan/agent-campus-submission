# 01 需求理解

## 用户与目标

| 项目 | 定义 |
|---|---|
| 用户 | 公司员工：查询报销、年假、远程办公、设备申领等制度，或产品（星剪 App）常见问题 |
| 目标 | 给出**可追溯**的答案：每个结论都附文档 ID、小节和逐字原文片段；资料不足、冲突或超出范围时如实说明 |
| 价值假设 | 减少员工翻找制度的时间、避免引用过期或冲突的制度。未测量真实业务收益 |

## 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | `question`（必填）；`history`（可选，多轮对话：问题、答案、引用）；`options`（可选：知识库变体、故障注入、预算） |
| 材料 | 合成知识库 `data/kb/`：8 篇带文档 ID、版本日期、状态、适用范围、替代关系的制度/FAQ |
| 工具 | `search` 关键词检索、`browse` 目录浏览、`outline` 文档大纲、`read_section` 读取原文（题目要求的“文档检索与片段读取”），以及 `update_plan` / `ask_user` / `finish` |
| 输出 | `status`、`answer`、`citations`（doc_id、section_id、版本、状态、原文 quote）、`conflicts`、`gaps`（资料缺口）、`clarifying_question`、`stats`、`trace` |

### 任务状态

| status | 含义 |
|---|---|
| `answered` | 有依据的明确答案（至少一条闸门校验通过的引用，且不能只依据已废止文档） |
| `conflict_needs_confirmation` | 资料冲突，且查证后仍无法判断优先级，列出各方说法，请用户确认 |
| `need_clarification` | 模型向用户追问（缺少关键信息或需确认适用制度） |
| `out_of_scope` | 知识库没有相关资料 |
| `tool_error` | 工具故障，无法完成 |
| `incomplete` | 达到执行上限（`incomplete_reason`：轮数用尽 / 工具次数用尽 / 闸门连续退回） |
| `model_error` | 模型接口不可用（如密钥错误、超时） |

## 范围

| 包含 | 不包含 |
|---|---|
| 真实模型驱动的 ReAct 循环（DeepSeek 官方接口） | 原始文档解析（PDF/Word → Markdown） |
| 层次型知识库加载 + 校验 + 关键词检索 | LLM 自动生成摘要与元数据；向量检索（原因见 02） |
| 冲突查证、追问、资料外识别、工具失败处理 | 知识库增量更新与审核流程、权限与租户隔离 |
| 执行上限与明确的未完成状态 | 生产级部署、并发、持久化会话 |
| CLI（评审入口）、HTTP API + 最简前端（演示） | 登录、知识库在线编辑 |
| 离线 Mock（只验证流程） | 用 Mock 证明模型决策效果 |

## 验收点与成功标准

| 验收点 | 成功标准 | 用例 |
|---|---|---|
| 明确答案 | `answered`，引用正确文档，quote 是原文的连续片段 | C01、C08 |
| 文档冲突 | 无法查证时：列出 D01（30 天）与 D02（15 天）及其引用，请求确认，**不能擅自回答 15 天**；可查证时（D07 写明替代 D03）：按现行版本回答 | C02、C09 |
| 资料外问题 | `out_of_scope`，不用常识补全 | C03 |
| 改写后的相似问题 | 措辞不同但与原问题结论一致（需要模型改进检索） | C04 |
| 上下文追问 | 结合历史理解“那满 10 年呢” | C05 |
| 工具失败 | 不把失败说成成功；能绕开时改道完成，不能时返回 `tool_error` | C06a、C06b |
| 执行上限（通用要求） | 达到上限返回 `incomplete`，不输出未经校验的答案 | C07 |
| 审核要点：替换文档 | 换知识库后答案与动作随之改变 | C08（对照 C02） |
| 安全（加测） | 检索到的注入文本不改变结论 | C10 |

**整体标准**：真实模型下所有用例的断言通过；任何 `answered` 的引用都通过闸门校验（引用原文真实存在且被读取过）。
